# Demo 展示路线

在仓库根目录运行 `python start.py`，访问 http://127.0.0.1:5173。四个账号初始密码均为 `Campus2026!`，登录页可直接选择身份。

## 1. 总览与档案

使用 `center` 进入工作台，展示学生数、测评覆盖率、关注分布、近期趋势和优先个案。进入学生档案，按学院/等级筛选、搜索学生，打开个人档案查看历史；可以新增/编辑虚构学生，并下载 CSV 模板进行导入。

CSV 使用 UTF-8，重复学号和越权学院返回对应错误行。没有测评的新档案默认分数 0，应通过测评记录判断是否已经测评，而不是把默认分数当一次健康结论。

## 2. 学生体验

退出并选择 `student`。查看林同学的健康档案，完成心理自评的 9 项问题。提交后保存总分与关注提示，页面刷新仍可查看。演示需要触发重点关注时，可让总分达到 15；第 9 项非零会要求优先人工复核，请说明这是演示操作。

进入每日打卡，选择心情、睡眠、压力和可选备注。当天重复保存更新同一条记录，不重复新增。

量表参照 [PHQ-9 原始量表说明](https://www.apa.org/depression-guideline/patient-health-questionnaire.pdf)，中文措辞为演示表达。规则帮助启动关怀工作流，不提供诊断。

## 3. 完整个案闭环

切换 `center`，在预警管理搜索林同学：受理 → 添加沟通/咨询记录和随访日期 → 转入复评 → 填写人工复评与关闭说明。打开时间线观察记录保留；关闭后进入“已完成”，不会自动清除最新关注等级。

干预随访可筛选进行中、今日及逾期、全部记录。消息中心可以查看对应站内提醒并标记已读。没有真实邮件或短信发送。

## 4. 角色隔离

`counselor` 只显示计算机学院的档案和个案。`student` 只显示自己的档案与记录，不能读取其他学生；`contact` 仅显示必要的关怀提醒，不显示测评答案、分数或睡眠历史。

## 5. 模型实验

在中心账号打开“模型实验室”，先选择 101 条匿名问卷，展示 5 折交叉验证、特征筛选及 Logistic / J48 对比；再切换十万条合成数据，展示分层 60/20/20 划分、四模型指标、ROC、混淆矩阵，以及验证阈值后的测试结果。输入生活方式特征比较三种模型概率，查看逻辑回归系数、树规则和森林摘要，导出评估 JSON。

该实验可以证明 Java 建模、评估与推理链路完成；合成数据的高分或低分都不代表真实校园预测有效。模型输入与规则预警使用不同标签，互不冒充。

## 6. 可持续运行

重启保留业务操作；首次数据初始化只执行一次。下载后的数据被 Git 忽略，别人 clone 后执行数据准备脚本即可复现。结束演示按 Ctrl+C 停止前后端，数据库、模型、缓存分别管理，避免误删共享工具。
