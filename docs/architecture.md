# 系统架构

项目采用单仓库、模块化单体后端与独立 Vue 前端。浏览器通过同源 `/api` 访问服务，Vite 开发代理连接本机 Spring Boot；H2 文件库由 Flyway 迁移，Hibernate 仅验证结构。

```mermaid
flowchart LR
  U[四类用户] --> V[Vue / 路由与共享组件]
  V --> S[Spring Security / Session / CSRF]
  S --> P[PortalController / DTO 校验]
  P --> B[PortalService / 记录范围与业务事务]
  B --> H[(H2 / Flyway)]
  S --> M[MachineLearningController]
  M --> W[Weka / 训练·验证·推理]
  D[公开 CSV / 固定 SHA256] --> W
  W --> A[忽略的模型与评估文件]
```

| 实现位置 | 职责 |
| --- | --- |
| auth、config | Cookie 会话登录、退出、CSRF、认证入口 |
| common | 可读错误响应和输入校验失败处理 |
| demo | 固定演示账号、CSV 解析、首次数据初始化 |
| portal | 档案、测评、打卡、规则分级、预警、干预与站内通知 |
| ml | 两种数据模式、Weka 训练/评估/推理、模型与指标产物 |
| system | 匿名健康与 Demo 元数据 |
| frontend/src/views | 工作台、档案、模型实验、个案、学生与联系人页面 |
| frontend/src/components | 图表、状态反馈、学生抽屉、个案抽屉、图标与分级徽标 |

服务端对角色和记录归属同时授权：中心全校、辅导员本学院、学生本人、联系人自己的最小通知。辅导员收件箱及标已读操作按学生当前学院复核范围，避免学生转出后仍能访问旧提醒。前端导航仅改善体验，不作为安全边界。所有写请求携带 CSRF 令牌；登录后重新获取令牌，退出销毁会话。

业务链路：自评/打卡 → 事务内记录 → 规则评估 → 非常规关注触发预警 → 站内提醒 → 受理 → 干预记录 → 人工复评 → 关闭。测评响应区分 PHQ 测评级别 `riskLevel` 与结合打卡的综合规则级别 `ruleRiskLevel`；档案显示最新综合结果，活动预警保留已触发的较高等级直至人工处理。

测评有请求幂等键与稳定排序序号，提交时综合规则级别持久化，幂等重试返回原结果；相同内容的当天打卡重试直接返回原记录，仅编辑备注时也不重复规则评估。打卡有学生/日期唯一约束。同学生写操作在事务内锁定学生行，串行更新信号与个案，避免并发重复预警或覆盖已关闭个案的状态。一个学生仅有一个活动个案；等级升级或新的第 9 项非零自评会刷新活动个案并再次提醒。关闭保留学生关注等级，后续有效新提交仍按最新测评与近期打卡评估；无活动个案且等级非 `LOW` 时建立新个案。

待复评个案出现上述新信号后回到 `ACCEPTED`，需要重新干预并转入复评。人工复评与 5–600 字符的关闭说明足以完成关闭，不强制新增学生自评。首次受理人保持不变，后续行动作者记录在干预时间线。随访以 `NONE / PLANNED / SUPERSEDED / CANCELLED` 区分未安排、当前计划及历史；每次新干预都替代旧计划，包括未填写新随访日期的情况。工作台只展示当前计划。

机器学习是独立实验通道。用原始公开数据建立监督模型，预测数据集标签；不以合成平台历史训练，也不自动用模型概率创建四级预警。这样保留清晰的标签语义和可解释的人工关怀流程。

已保留的学生 JPA 实体/Repository 支持基础持久化测试；实际 Demo 查询由 JdbcTemplate 执行。纯注释空包和过时占位说明已可恢复归档。两份模型实验分别缓存特征模式、分类器和阈值。模型仅使用本次进程训练对象，不从任意上传文件反序列化。
